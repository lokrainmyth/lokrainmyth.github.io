# PROJECT DAWN

## Philosophy

PROJECT DAWN is not an album website.

It is an invitation to begin a journey.

The listener does not simply press Play. They enter a symbolic path that gradually transforms from night into dawn. Music, interface, interaction and memory become one continuous experience.

The website should never feel like a streaming service.

It should feel like entering a quiet place that remembers you.

---

# Core Idea

Io is the first conscious chapter of the Lo.Krain universe.

The previous albums existed before the myth was understood.

Io reveals the entire mythology from above.

The listener first experiences the album.

Only afterwards do they discover the deeper world.

The order is important.

Music comes first.

Meaning comes afterwards.

# Core Principles

The interface must remain minimal.

Silence is part of the design.

Large empty spaces are intentional.

Animations must always be slow.

Nothing should flash.

Nothing should shout.

Everything should feel inevitable.

---

# Visual Language

Black.

Warm white.

Fog.

Morning light.

Occasional gold.

Soft blue inside the myth.

No aggressive gradients.

No modern glossy UI.

No glassmorphism.

No gaming aesthetics.

---

# Playlist Rules

Playlist behaves like an airport departure board.

Titles partially disappear.

Letters slowly return.

Completed tracks remain permanently transformed.

Completed tracks should eventually receive:

warm golden typography

subtle golden ring

soft internal glow

occasional light reflection

Completion must feel rewarding without becoming decorative.

---

# Audio Rules

The album must always remain the center.

Ambient sounds support the journey.

Never compete with the music.

Intro currently uses wind.

Possible future replacement:

a distant airplane taking off.

---

# Outro

# Things That Must Never Change

Music is always first.

Minimalism over decoration.

Atmosphere over information.

Curiosity over explanation.

Slow over fast.

Meaning over functionality.

The listener should leave feeling they have travelled somewhere.

Not simply listened to an album.

# Scene Architecture

PROJECT DAWN is divided into scenes rather than pages.

Current sequence:

Intro

↓

Journey

↓

Outro

↓

Theo

↓

Myth

↓

Return

Each scene is responsible for one emotional transition.

Scenes should never overlap.

Only one primary scene should be visible at a time.

Transitions should always fade rather than instantly switch.

# Scene Rules

Every scene has only two public actions.

openScene()

closeScene()

No scene should directly manipulate another scene.

Scene transitions should always be requested rather than forced.

# Architecture Rule

Legacy systems are removed immediately after replacement.

Old and new navigation must never coexist.

Every transition should have only one implementation.

# Transition Rule

Every transition should preserve the previous scene underneath.

The world never disappears instantly.

It slowly fades into the next experience.

Darkness is a bridge rather than a cut.

CURRENT PHASE

The project is no longer in the architecture stage.

Core systems are considered complete.

Current development focuses only on polishing,
visual rhythm,
micro-interactions,
light,
timing,
and emotional continuity.

No new major systems should be introduced unless they extend the existing mythology.

The site is not a landing page. It is a journey with an intro, a dawn, an outro, and a continuation. Every transition should feel like entering another state rather than opening another page.
